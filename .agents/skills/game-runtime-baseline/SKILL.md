# 游戏参考运行基线

工作区索引见 projects.json，原包在 resources/；各项目是 projects/ 下的独立 Git 仓库。先读目标项目 AGENTS.md、project.config.json 和 docs/REBUILD_PLAN.md，项目进度和轻量验收摘要写回项目仓库。工作区路径可由 REBUILD_WORKSPACE_ROOT 指定。


阅读工作区 AGENTS.md、docs/REBUILD_PLAN.md 和目标包依赖说明。原包保持不变，在 `reference/<game>/` 进行适配。

- 静态追踪入口、脚本顺序、资源基址、SDK 顶层调用、Service Worker 和存档键，再选择最小适配；逐项记录修改与行为影响。
- 用本地 HTTP 服务及独立存档建立参考运行。使用专用浏览器上下文；只处理本参考环境的缓存和 Service Worker。
- 对缺失平台能力明确实现所需接口、异步返回和回调时序。区分不可用、取消、失败、成功；模拟奖励场景必须标记，不能伪称平台真实响应。
- 记录实际网络请求、加载失败和控制台错误，区分核心资源缺失与已知不支持的平台能力。
- 保留原版时间/随机语义。需要固定种子或捕获输入时记录插桩位置；无法固定的随机源保存初始化结果。
- 先采集一个完整玩法闭环，再扩展失败、重开和存档恢复。截图附视口、像素比、状态和采样时刻。
- Unity 原包重建配合 [unity-package-rebuild](../unity-package-rebuild/SKILL.md)：由资源/方法分析确定观测目标，优先记录事件、数值和状态转移；截图不是内部规则的唯一依据。调试/插桩或状态注入实验与未改动的自然游玩基线隔离，记录探针和行为影响，不据实验强制结果宣称自然通关。

原引擎版本、布局生成、缓存与平台渠道差异从目标项目说明和包内依赖审计读取；不要把某一游戏的特性固化为所有参考版本的行为。

交付本地启动命令、适配清单和 `evidence/<game>/runtime-baseline.md`；证据注明「适配后参考版本」。无法运行浏览器时交付静态发现及缺失能力，不把静态检查写成游玩成功。
