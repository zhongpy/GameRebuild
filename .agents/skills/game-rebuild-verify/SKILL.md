# 重建功能对照验收

工作区索引见 projects.json，原包在 resources/；各项目是 projects/ 下的独立 Git 仓库。先读目标项目 AGENTS.md、project.config.json 和 docs/REBUILD_PLAN.md，项目进度和轻量验收摘要写回项目仓库。工作区路径可由 REBUILD_WORKSPACE_ROOT 指定。


阅读 AGENTS.md、当前重建计划与目标游戏的运行证据。选择本次改动影响的场景；已有稳定结果无需无关重复验证。

- 每个预期结果注明源码证实、运行观察或推断。无参考证据的行为只能标记为临时实现，不能宣布还原通过。
- 对齐版本、初始存档、生成状态、输入及时间条件。参考与重建使用同一输入序列；物理差异需同时检查更新频率、碰撞顺序和随机源。
- 状态对照覆盖输入是否接受、状态转移、胜负、奖励和存档；只检查渲染对象存在不足以验证规则。
- 图像对照固定视口、像素比、镜头、UI 状态和时间；合理屏蔽范围与容差需写明原因。检查图层、材质、布局、字体、动画及音效触发。
- 源码应具备可辨认的规则模块、数据和边界接口；单纯包装压缩发布脚本不满足可维护源码目标。
- 对发现的问题新增能捕获行为差异的最小回归场景。改动低影响文档无需增加测试。

交付 `evidence/<game>/verification.md` 或现有报告中的对应记录：场景、证据引用、运行方式、预期/实际、通过/失败/未验证、容差及已知差异。失败项目保留复现输入；更新项目仓库 docs/REBUILD_PLAN.md 的实际进度。
